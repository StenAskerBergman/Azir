# Runeterra Theme Replacements

One first technology candidate per country for the 990 campaign. A candidate can keep an existing technology when it already occupies the right role. The table proposes a playable effect and an unlock, so each idea can be reviewed against the country's route and the underlying HOI4 mechanic.

The starting roster covers 37 tags from the 990 bookmark and baseline state-history comparison in the local Azir, Runeterra, and Quarior stack. The audit retains all same-layer alternatives and finds 44 possible starting tags. Seven of those have candidates in the conditional table because their starts depend on competing state histories. That table contains 17 tags in all. Candidate names and mechanics are mod proposals. For smaller countries with sparse published lore, start from the named state's geography and current campaign role. Resolve competing histories before adding tech that depends on those starts.

## Existing technology collection

The 19 local technologies are in [azir_runeterra_theme_replacements.txt](../common/technologies/azir_runeterra_theme_replacements.txt). They retain their original IDs, bodies, localization, positions, gates, and callers. Piltover, Zaun and Nazumah have one researchable country-specific item each. Shurima has one scripted unlock, Xerath has two, and the Void has twelve. Improved Dozer Blade remains a shared research item. The other entries in the candidate tables are proposals.

Run **python -B tools/runeterra_theme_replacements.py** to list the country proposals and local implementation IDs. Add **--country IXT** for one country. Use **--audit-roster RUNETERRA QUARIOR** with the installed mod folders to check coverage against the state history. The audit reports competing owners instead of choosing one.

For the next technology, check that the country and route exist, select the narrowest effect that expresses the candidate, author its final unlock and asset links, and verify the normal in-game path. Run the inventory before adding it. Once a technology file has been reviewed, **--consolidate FILE** moves it into the collection, backs up the source, and verifies that the before and after definitions are identical. The tool checks local IDs. Check potential conflicts with active dependencies before consolidating.
